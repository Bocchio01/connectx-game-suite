Detailed Description

Exact ("strong") solver: computes the game-theoretic value of a position, assuming both players play perfectly until the end of the game.

It is a negamax search with alpha-beta pruning made fast by

  • the bitboard Position (a move is a handful of CPU instructions),
  • never searching moves that lose immediately (Position::nonLosingMoves),
  • move ordering by the number of winning threats a move creates,
  • a transposition table,
  • an iterative null-window search that narrows [min, max] around the true score with a few very cheap "is the score greater than m?" questions.

Scores follow the convention of Pascal Pons' Connect-4 solver: score = 0 the game is a draw; score > 0 the player to move wins; he still holds (score - 1) stones in his hand when he connects, so larger = faster win; score < 0 the player to move loses, -score is how quickly (-1 = the opponent wins with his very last stone). On the empty 6x7 board the score is +1: the first player wins, but only with the last stone he can play.

Everything is exact for any supported board and any connect length; the running time grows quickly for early positions of large boards (an empty 6x7 board takes minutes), so the search can be bounded in nodes and time.
