Detailed Description

Qt facade over the blocking network Client library.

The controller lives in the GUI thread and is the ONLY place that touches the Client. Every connection is a "session" that owns a Client, a worker thread (which executes the blocking request/response calls one at a time) and the Client event thread. Results and server events are delivered to the GUI thread as queued signals, so receivers never need locks. Slots must be called from the GUI thread.

Guarantees:

  • joined() is always emitted before the first stateUpdated() of that game, even if the server's state broadcast overtakes the join response;
  • signals of a session that has been ended (disconnect, new connection...) are dropped;
  • a request refused by the server is reported at once, with the friendly text of the error;
  • destroying the controller (or ending a session) never blocks for long: a request that is waiting for its answer is released by closing the connection, and the only call that cannot be interrupted, the TCP connect to a host that does not answer, is abandoned: its worker cleans itself up when the call returns (the connect gives up after a few seconds).

One game per connection: to play another game, call reconnect() and join again.
