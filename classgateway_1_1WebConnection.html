Detailed Description

A browser connected to the gateway: a socket that speaks WebSocket.

One thread reads (receive()), any thread can write: the frames of different threads do not get mixed up.

◆ receive()

websocket::Reader::Event gateway::WebConnection::receive ( int timeout_ms)

Waits up to timeout_ms for what the peer sends next. Pings are answered here, and so are a Close frame and a protocol violation (by closing), so whatever comes back is either a message or the end of the connection. The result is of type NONE if time ran out.
