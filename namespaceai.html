◆ Encoding

enum class ai::Encoding : uint32_t
strong

How a position is presented to a neural network. Every encoding is relative to the player to move ("mine" = the player who has to play) and is flattened as NHWC: out[(row * cols + col) * planes + plane], with row 0 = top.

RAW 2 planes: 0 my stones, 1 the opponent's stones. The network must discover everything by itself, e.g. what a "three in a row" is.

TACTICAL 5 planes: the two above, plus 2 the empty cells where I would complete a line, 3 the empty cells where the opponent would complete a line, 4 the cell where a stone dropped in each column lands (the playable cells). The 1-move tactics (win now, block now, do not play under a threat) become trivially visible; the network can spend its capacity on strategy.

WINDOWS the 2 raw planes followed by 2 numbers for every line of connect cells ("window") of the board: the share of the line that I hold if the opponent holds nothing there (else 0), and the same for the opponent. This is the information used by the classic heuristic evaluation, as network inputs.

The encoding is stored in the model file, so every program that evaluates a network (C++, Python, the Arduino sketch) knows how to build its input.

◆ evaluate()

int ai::evaluate ( const Position & position)

Static evaluation of a non-terminal position, from the point of view of the player to move (positive = good for the player to move).

The classic "open lines" heuristic: look at every line of connect cells; a line that contains stones of one player only is an opportunity for that player, worth more the more stones are already in it (1, 10, 100 ... points). Stones in the central column(s) get a small bonus because they take part in more lines.

◆ loadSharedModel()

std::shared_ptr< const nn::PolicyValueNet > ai::loadSharedModel ( const std::string & path)

Loads a model file (".cxnn") and shares the network between all the agents that use the same file: a tournament creates one agent per thread, but the weights are loaded once. PolicyValueNet::predict() is thread-safe, so this is fine.

The cache notices when the file changes (size or modification time), which matters while a training run keeps overwriting its checkpoint.

Exceptions
std::runtime_errorif the file cannot be read

◆ resolveModelPath()

std::string ai::resolveModelPath ( const std::string & path)

Finds a model file. A path that exists is used as it is; otherwise, for relative paths, the folder "models" next to the executable (or next to its parent folder), the folder of the executable, "./models" and the directories listed in the CONNECTX_MODEL_PATH environment variable are tried (also adding the ".cxnn" extension). So "connectx_6x7" is enough to name the pretrained model that is installed with the programs.

Exceptions
std::runtime_errorlisting the places searched if nothing is found
